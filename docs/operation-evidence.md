# 本轮操作与执行事实

CornAgent 使用服务端工具回执判断本轮操作状态。模型正文、工具参数、`ok: true`、草稿和准备好的计划都不能单独证明业务数据已写入。

## 工具声明与回执

业务写工具在 `ToolDefinition` 中声明 `effect="write"`，并返回结构化 `operation_receipt`：

```python
return {
    "ok": True,
    "operation_receipt": {
        "state": "committed",
        "changes": [{
            "resource_id": "record-123",
            "resource_type": "record",
            "title": "项目计划",
            "action": "update",
            "fields": [{"label": "状态", "before": "草稿", "value": "进行中"}],
            "href": "/records/record-123",
        }],
    },
}
```

`resource_id` 和 `resource_type` 定位实际资源；`action` 支持 `create`、`update`、`delete`、`attach`。`fields` 只描述回执确认保存的值，不从提交参数补造字段原值。没有回执字段详情时，界面明确说明详情缺失。链接仅接受应用内路径；已删除资源不提供链接。

已有工具可声明 `outcome_projector`，把其完整结果转换为上述公开回执。投影器必须只输出允许展示的字段。没有该适配器时，运行器使用 `project_result` 的公开结果判断状态，私有工具结果不会通过操作卡泄漏。投影失败时状态为 `unknown`，不会改变工具已经执行的业务操作。

| 状态 | 含义 |
| --- | --- |
| `committed` | 回执明确确认已提交；可展示该回执中的资源和字段变化 |
| `partial` | 批次中只有部分操作已提交；保留成功子项，其他项目分别显示 |
| `draft` | 已准备或生成草稿，尚未确认提交 |
| `noop` | 取消、未执行或明确没有变化 |
| `failed` | 操作被拒绝或返回明确失败回执 |
| `unknown` | 缺少确认，或证据矛盾、执行后异常导致结果不明；重试前需要核对原回执或目标状态 |

批量工具在 `items` 中返回每项的独立回执。即使顶层 `ok=false`，明确提交的成功子项仍可贡献变更；失败、草稿和未知子项不会成为“已保存”。只有部分状态而没有逐项确认的资源，也不能推断为已提交。

`read_only=True` 或 `effect="read"`、`effect="control"` 的工具不贡献业务变更，即使结果包含同名回执字段。未声明 `effect` 的旧普通工具仍可运行，但结果仅作为未确认操作；框架控制工具不计入业务修改。

## 持久化与展示

服务器将 `operation_outcome` 与 `changes` 加入已有 `tool_call` 内容块的 metadata，并与工具结果一起提交数据库，再发布 SSE。聊天页和嵌入侧栏共用操作卡；工具进度折叠后仍能查看已提交资源、前后字段值以及未解决的状态。刷新和服务重启从同一份内容块恢复；重复快照按内容块 ID 更新，不重复计数。

每条公开操作 metadata 的完整 JSON 上限为 32 KiB；超出时先保留状态计数和资源摘要，再按顺序保留可容纳的完整字段，并标记详情已截断。当前 Run 的操作资源详情合计限制为 128 KiB，优先保留最新详情；较早操作的状态和计数继续保留。完整工具回执独立保存，公开详情裁剪不修改回执，可使用 `read_tool_result` 分页回读。状态计数和其他消息内容仍占用 checkpoint 空间，因此上述详情预算不是整个 Run 的容量承诺。

这份汇总只覆盖当前 Run 的实际工具执行，不会把历史对话中的成功操作算成本轮成果。界面语言和主题只改变展示，不改变回执、字段值和展开状态。

## 回答中的事实边界

每次模型请求都携带从持久化操作 metadata 得出的执行状态计数，并明确约束最终回答：按回执区分已提交、草稿、失败和未知；失败批次不能抹掉成功子项；结果不明时不能通过重复写入“确认成功”。完整工具输出被截断时，需要通过 `read_tool_result` 回读相关证据，再引用具体细节。

这是对执行状态与引用依据的确定性校验，不是对自然语言答案做全面真伪判定。工具回执记录的是执行时的结果；外部资源此后可能发生变化。需要确认当前状态时，应重新读取资源，并说明仍缺少的证据。
